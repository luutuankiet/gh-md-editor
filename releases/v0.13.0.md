# v0.13.0 — find overlay, command palette, file icons, Monokai, workspaces anywhere on disk

- **Find floats over the document instead of pushing it down** — the search box was inserted into the layout, so opening it shifted every line down by the box's own height while the scrollbar match ticks stayed where they were, and the ticks then pointed at lines that were no longer under them. It now overlays the top-right of the editor with the replace row collapsed until asked for, so nothing reflows. `Escape` closes it and clears the match highlighting; the double-click word highlight is a separate layer and survives, and reopening with `Cmd/Ctrl+F` brings the match highlights back.
- **`.env` files highlight, and `Cmd/Ctrl+/` toggles comments everywhere** — dotenv grammar covers `.env`, `.env.local` and `.env.*`: keys, values, quoted values and comments. Comment toggling already worked in the code languages and now includes dotenv.
- **Quick open and the command palette have an actual modal** — both were keyboard-only stubs that filtered nothing visible, so there was no way to see what a query matched. They share one modal now: fuzzy matching with the matched characters emphasized, the list narrowing on every keystroke, arrows to move and `Enter` to open. An empty quick-open query lists recently opened files, and a leading `@` switches it to symbols in the current file.
- **Selection expand and shrink work in every highlighted language, and the Mac arrow keys behave like the Mac** — `Ctrl+Shift+Left` grows the selection to the enclosing syntax node and `Ctrl+Shift+Right` shrinks it back, walking the same syntax tree that colours the file, so markdown, JSON, YAML, TypeScript, Python and the rest all get it rather than markdown alone. `Cmd+Shift+Left/Right` on macOS selects to the start and end of the line as every other Mac app does; it used to expand the block, which is what `Ctrl+Shift` is for.
- **The outline reveals, refreshes and resizes** — double-clicking an entry selects that node together with its full body in the editor instead of only scrolling to it. A refresh button rebuilds the outline from the current file, so it no longer goes stale after a save or an edit from another session. The outline and the explorer share a draggable divider, so the outline is no longer stuck at a fixed height.
- **`code-gh` opens things from the terminal you are already in** — `code-gh .` or `code-gh path/to/folder` anchors a tab on that workspace, `-r` reuses the current one instead of opening another, and a file argument opens the file. Relative and absolute paths both work, and every shell the editor spawns gets the port in its environment so the command finds its own server.
- **vscode-icons file icons, a Monokai Dimmed theme, and Format Document** — icons resolve per extension and are fetched only for the types actually on screen, so the initial bundle is unchanged. The theme covers the editor and the surrounding chrome rather than the editor alone. `Shift+Alt+F` formats the buffer; JSON only for now.
- **A workspace can be anywhere on the machine** — "Open Workspace" and "Open File" in the palette browse the whole filesystem from a path input, with the current workspace first and `..` to climb; arrow keys navigate into folders and only `Enter` from the input box commits. Paths outside the served folder now stay absolute end to end — open, search results, the git repository picker, the tab title, copy-full-path — instead of being reported as `../..`, a shape the server rejected on the way back in and which left the tab dead. The consequence is that the served folder is no longer a boundary: pass `--auth` on any server other people can reach.
