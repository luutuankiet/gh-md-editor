# v0.16.0 — Git, in the editor: dirty-diff gutters, a three-way merge editor, and blame

The server mode gains the parts of a git client that only make sense inside the text: marks in the margin where you have edited a tracked file, a real merge editor for conflicts, and blame in two shapes. Everything below is server mode (`npx @luutuankiet/gh-md-editor`).

- **Changed lines are marked in the gutter of every code tab** — a bar for modified, added and deleted regions, against the version in the index. Clicking one opens the committed text inline underneath, and offers to restore that region. The restore is a normal editor edit, so `Cmd+Z` takes it back; nothing is written to disk until the file is saved.
- **Conflicted files open in a three-way merge editor** — base, current and incoming side by side over an editable result, the shape VS Code settled on. Each side offers to take its version of the region, the result pane is a full editor so a hand-written resolution is possible, and "Mark resolved" saves and stages in one step. Conflicted files no longer appear under both staged and unstaged changes with a nonsense status letter.
- **Git blame, in a column** — who last touched each line, to the left of the line numbers. A run of lines from one commit is labelled once rather than forty times, so commit boundaries are legible at a glance; the sha, the full message and the exact timestamp are on hover. Lines you have edited but not committed are called out rather than attributed to whoever wrote them last.
- **Git blame, inline on the cursor's line** — a faint annotation past the end of the text, so the column is not the only choice. Hovering it opens the full commit record. Both blame modes are off by default, toggled separately from the command palette, and remembered by the browser: the column costs width, the annotation costs none, and most people want only one of them.
- **Compare any two points in a repository, not just the working tree against a base** — the incoming side now accepts a commit sha, a branch or `HEAD`, alongside the base. With both sides pinned to commits there is nothing on disk for a patch to land in, so those diffs are read-only rather than offering buttons that cannot work. Both choices are remembered per repository.
- **Editors and diffs re-read from disk when the window regains focus** — reverting a hunk in one view and switching back to another no longer leaves stale text on screen. The reload runs in the background and keeps the current content visible, so the spinner does not flash every time you tab back.
- **Two new endpoints** — `GET /api/git/show` returns a file at a given stage or commit, and `GET /api/git/blame` returns per-line authorship. Blame is the first git call in the server that runs without blocking the event loop: a file with a deep history can take a full second, which every other request would otherwise have waited out.
