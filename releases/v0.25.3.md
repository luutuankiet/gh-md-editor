# v0.25.3 — find in a diff stops hiding its own matches, and a tree compare row can open either side

- **A find match inside a folded region now unfolds it.** The diff folds long unchanged stretches behind a grey `N unchanged lines` strip. The text is still in the document, so the search cursor walks it and the match counter counts it — only the view drops it. Stepping through find would report `5 of 24`, scroll to a plausible place, and highlight nothing at all; on one real diff that happened on two of the first ten steps. The strip now opens when a match lands in it, on both columns at once, and the revealed line is centred rather than left flush against the bottom edge of the viewport.
- **Both columns unfold together, on purpose.** Expanding one side alone leaves it taller than the other and the merge view papers over the difference with a spacer — the two sides stop lining up, which is the one thing a diff must not do. Clicking a strip by hand has always paired the sides; arriving there by find now does the same.
- **Match ticks say which column they came from.** Each pane has its own find panel and its own query, and both feed the one scrollbar the split view has. Two live searches put seventy identically styled marks on a single rail with nothing to tell them apart. Each column now has its own lane on that rail.
- **Matches behind a fold are drawn hollow.** Every match inside one collapsed region shares that region's single y position, so five hits read as one solid tick and the rail silently under-reported. A hollow mark says there is more there than one line; stepping onto it opens the strip and the marks separate.
- **Opening find no longer knocks the two columns out of alignment.** CodeMirror's base theme puts the find panel in flow above the editor. Harmless in a single editor, wrong in a diff: opening find in one column pushed that column's rows down by the panel's height — 32px, about two lines — and the sides stopped lining up until the other column's panel happened to be open too, at which point they silently lined up again. The panel floats over the text now, so both columns keep their full height whatever is open.
- **Tree compare rows can open a file as it was at either ref.** The commit graph has offered this since v0.21.0; the tree compare panel's rows had no actions at all beyond opening the diff. A row there spans two refs rather than one commit, so it offers up to two: the base side, and the incoming side when that side is pinned to a ref rather than left as the working tree. Added files get no base entry and deleted files no incoming one. There is also a shortcut to the current working copy, matching the vocabulary the commit graph already uses.

No storage format change and no server change. The diff fixes are browser-side and apply to the web app, the server IDE and the VS Code extension alike; the tree compare panel is a server-mode surface.
