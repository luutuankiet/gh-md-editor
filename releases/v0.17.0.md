# v0.17.0 — the file explorer grows hands, and the server upgrades itself

Most of the work you do to a project is not editing a file — it is making one, renaming it, moving it somewhere better, or finding the folder it should live in. All of that meant dropping into the terminal. It doesn't any more. Everything below is server mode (`npx @luutuankiet/gh-md-editor`).

## Explorer

- **Right-click to create a file or a folder.** New entries land where you clicked — in the folder itself, or beside the file you aimed at. A name typed as `a/b/c.ts` creates the folders on the way, the same way the quick-open path box already did.
- **Double-click a name to rename it.** Editing happens in the tree, on the row, with the extension pre-deselected so the common case is one keystroke. Renaming a file that is open moves its tab with it.
- **Drag files and folders to move them.** Dropping onto a folder moves the entry inside it; the drop target is drawn as you pass over it, and a move that would put a folder inside itself is refused rather than attempted.
- **Ctrl/Cmd-click now includes the file you already had open.** Previously the click that opened a file did not count as a selection, so the first Ctrl-click silently dropped it and a right-click acted on one fewer file than the highlighting showed. Shift-click had always behaved correctly; the two now agree.
- **Recent workspaces sit above the explorer**, collapsed by default, ten deep. Anchoring at a home directory and opening into a subfolder every session is the usual pattern, and this makes the second half of it one click. Right-click removes an entry; nothing validates that the path still exists, because a folder that has gone is worth seeing rather than hiding.

## Editor

- **The path above the editor is a breadcrumb trail.** Click any segment to browse from there — files and folders both — the way the same strip behaves in VS Code.
- **`Cmd/Ctrl+Shift+D` selects every occurrence of the selection**, the all-at-once counterpart to `Cmd+D`'s one-at-a-time walk. With nothing selected it widens to the word under the cursor first. Also in the command palette.
- **Editor tabs can be dragged into a new order.** Dragging a tab out to split the view already worked; reordering within a group was the missing half.

## Upgrading

- **`Upgrade Server` in the command palette does what the cli's `upgrade` does, without leaving the page.** The version it is running now sits at the right end of the title bar; click it to upgrade. Both exist for the same reason: once a client can move its own server onto a new release, it needs to be able to see which one it is on.
- **The page reconnects itself.** An upgrade fetches a new tree, kills the old server and starts a replacement on the same port, which means the page that requested it is served by a process that no longer exists by the time it finishes. It watches for the port going away and answering again, then reloads onto the new bundle. Down-then-up rather than a version change, because a forced upgrade can legitimately land on the same version and a version-only watch would wait forever.
- **It refuses to upgrade a server running from a source checkout.** A git working copy is not something a click in a browser should replace with npm's published build. The title-bar badge is inert on those servers and says why.
- **It refuses to upgrade a tunnelled server.** A restart mints a fresh public url, and a bare `--tunnel` mints a fresh auth token too, so the page asking for the upgrade could never reconnect to what came back. Those still upgrade from a terminal, where the new url is printed.
- **No prompt before killing terminal sessions**, matching the cli. They are collateral of a restart you asked for, not something being discarded behind your back.
- **The package being installed is fixed in the server.** It is never read from the request: the endpoint sits behind the same token as the terminal, and a client-supplied package spec would turn that token into arbitrary code execution.
