# v0.24.0 — every tab remembers its own view

Until now a handful of view settings were single values shared by the whole
editor: turn word wrap off to read a minified file and it went off for the
markdown tab behind it too. This release moves that state down to the tab. Wrap,
scroll position, diff layout and a hand-picked language are remembered per tab,
in the browser, and restored on a tab switch or a reload.

## Word wrap is per tab, and Opt+Z reaches the diff editors

Wrap was one flag for the entire editor. A tab now carries its own override, and
only once you have actually toggled it there — tabs you have never touched keep
following the editor-wide default, so the setting you had before this release is
still the setting you get.

The `Alt/Opt+Z` chord also works in the diff and merge editors, which it did not
before. It was matched against the character the keystroke produces, and on
macOS `Option+Z` produces `Ω`; in the panes that had no binding of their own the
keystroke fell through and inserted that symbol into the document. It is now
matched on the physical key and handled for the whole window, so the diff panes
answer it like every other editor and the dedicated wrap button is no longer the
only way.

## Tabs return to where you were reading

Switching away from a tab and back put you at the top of the file. Each tab now
remembers its scroll position — code, markdown and diff alike — and returns
there, including after a full page reload.

Diffs needed more than storing a number. The split view folds every unchanged
region as it installs and measures the result over several frames, so for the
first of them the document is far shorter than the offset being restored, and a
single assignment silently clamped to the top. The restore now waits until the
content can actually hold the position, and gives up rather than leaving a timer
armed if the document is genuinely shorter than it used to be.

## Diffs remember how you were reading them

The choice between the side-by-side, inline and hunk-list layouts was
editor-wide and reset on every switch. It is now remembered per tab, so a diff
being read side by side stays that way while another stays a hunk list.

## A language you picked by hand stays picked

An unsaved buffer takes its syntax highlighting from its filename, and it has no
filename — so pasting YAML into a new tab and choosing YAML from the picker was
the only record of what the text was. That choice lived in the tab's component,
and the component is destroyed on a tab switch, so coming back dropped the
document to plain text. The pick is now stored with the rest of the tab's view
state and outranks whatever a filename would imply. It is validated against the
current language list on read, so a name cached by an older version cannot send
the loader hunting for a grammar that no longer exists.

## Find works inside a diff, one side at a time

A diff had no find of its own, so `Cmd/Ctrl+F` reached the browser and opened
its find bar over the page. That searches the rendered document, which in a diff
cannot see the folded-away unchanged regions or anything below the viewport — so
the one place a find is most needed was the one place it could not be trusted.

Each pane now carries its own find panel with its own query, since the string
being looked for is usually present on one side only. The chord is answered from
anywhere in the tab, routed to the side being edited when the cursor is in
neither pane. `Mod+G` is left to the browser, matching what the code editor
already does; the panel's own field still steps through matches.
