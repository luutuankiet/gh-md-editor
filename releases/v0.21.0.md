# v0.21.0 — trees where there were lists, and a clipboard in the explorer

Two bugs in the diff views that looked intermittent turned out to be neither,
and three places that showed you a flat list now show you a tree.

## Split diffs scroll again

A split diff would render the whole file and then refuse to scroll past the
first screenful — sometimes. Switching to inline or hunks brought the scrollbar
back, which made it look like a rendering race.

It was not. The merge view hands vertical scroll to its outer container and
sizes the editors to their content; a height rule of ours capped that container
and its children to the same height, so the element that owned the scroll had
nothing left to scroll. Inline and hunks each own their scroller, which is why
they always worked. The rule is gone.

## The first commit of a repository opens

Clicking any file in a root commit answered `unknown ref`. A commit with no
parent has nothing to diff against, so the graph asks for git's empty tree — and
ref resolution accepted only refs that peel to a commit, which an empty tree
never does. Tree-ish refs are accepted now, so first commits diff like any
other, in the graph and in the file-at-a-ref view alike.

## Commit details are a tree

The changed-file list in the graph was a column of full paths, every one wearing
the same prefix. It is now a folder tree with single-child chains collapsed into
one `src / dbtcx` row, and each file carries three actions on hover:

- copy its path
- open the file **as it was at that commit** — a read-only tab, not a diff
- open the current file

## Search results are a tree

Tree mode grouped by whole folder string, which put every folder at the same
level: in a large workspace that is a flat list of long paths wearing chevrons.
Results now nest one node per path segment, with per-folder hit counts that
include everything underneath, so a collapsed row still tells you what it hides.
The results header gained collapse-all (it toggles back), search-again and clear.

## Cut, copy and paste in the explorer

The explorer has its own clipboard, on the same keys as everywhere else:

| | |
|---|---|
| `Ctrl/Cmd+X` | cut the selection |
| `Ctrl/Cmd+C` | copy the selection |
| `Ctrl/Cmd+V` | paste into the selected folder, or into the folder holding the selected file |
| `Esc` | call off a cut |
| `Delete` | delete the selection |
| `↑` `↓` | move between rows |
| `→` `←` | open a folder / close it, or step out to its parent |
| `F2` | rename |

Cut rows fade and lean over until you paste them — a different kind of dim from
the one gitignored files already wear, so the two stay legible on the same row.
Nothing moves on disk until the paste. A copy stays on the clipboard so you can
paste it into several places; a cut is spent on its first paste. Pasting
something back where it came from duplicates it as `report copy.md`, and pasting
a folder into its own subtree is refused rather than attempted.

All of it is on the right-click menu too, next to the actions that were already
there.

## Recent workspaces name real folders

Opening a workspace with `code-gh .` remembered it as the folder "`.`", which
named nothing. Entries are stored as absolute paths now, so every row reads as a
name with its parent folder beside it, and each one offers **open in this
window** and **open in new window** on hover.

## Upgrading

Nothing to do. Recent workspaces stored by earlier versions are converted the
first time you load this one. An entry recorded under a different served root
may resolve to a path that no longer exists — right-click it and forget it.
