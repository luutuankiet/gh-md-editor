# v0.22.0 — finding out where a symbol is used, and dividers that move

Reading code in a browser tab has always had the same missing half: you can see
a function, but not who calls it. This release adds that, and makes the
three-pane layouts resizable while it is there.

## Every declaration says how many places use it

A quiet `12 references` row now sits above each function, class, interface,
enum and module in an open file. Clicking it opens a peek panel over the editor
— the lines around the first hit on the left, every location grouped by file on
the right. `↑` `↓` walk the hits and load each preview, `Enter` opens the file
at that line, `Esc` closes and leaves the editor exactly where it was.
`Shift+Alt+F12` opens the same panel for whatever word the cursor is on.

The counts come from one ripgrep per outline settle — every symbol name in a
single alternation, not one search per symbol — which is what makes this
affordable with no language server anywhere in the picture. Local variables
deliberately get no lens: a workspace-wide word count for `const n` is a
fiction, and an early build cheerfully reported 456 references to it.

Searches are scoped to the workspace folder rather than the whole served root,
so a root holding a dozen sibling checkouts never reports matches from projects
you did not open.

## Jumping to a symbol lands somewhere useful, and says so

Cmd/Ctrl-clicking an imported symbol resolves the import first — through
`tsconfig`/`jsconfig` path maps and `@`/`~`/`#` aliases — instead of stopping at
the first textual match in the file you are already in. When the jump lands, the
symbol it resolved to flashes, so a file that opens scrolled to line 400 does
not leave you hunting for what you clicked.

## Every divider moves now

The boundary between the two sides of a split diff is draggable, and so are all
three in the merge editor: current|base, base|incoming, and the one above the
result pane. Each remembers its position. A wall of blank space on one side of
a narrow diff was the most common reason to reach for a mode switch.

Dragging one boundary of a three-pane row no longer nudges the pane on the far
side of the other boundary — a stale grow-sum, captured while the panes were
still equal, used to shift the untouched pane by about 35px.

## The language picker sits above the editor

It used to live under it. On an unsaved buffer, where picking a language is the
only way to get highlighting at all, it is now next to the breadcrumb where it
is visible without scrolling.

## A mistyped command no longer starts a server

`gh-md-editor list-server` — singular — is not a command, and anything that is
not a command is taken as the directory to serve. So the typo started a real
server rooted at a folder that did not exist, on an auto-picked port, and
printed a URL as though it had worked. Near-misses on a real command name are
now rejected with a suggestion, and a root that does not exist refuses to start
at all rather than serving an empty tree.

## The version badge stops offering upgrades to itself

It reported "click to upgrade" whenever an upgrade was structurally possible,
never mind whether a newer version existed. Clicking it then restarted the
server onto the same version — taking every live terminal session with it, and
reporting success, because the restart genuinely happened. The badge now asks
npm what is published and says `already on the latest release` when that is the
answer. `upgrade --force` from a terminal still reinstalls deliberately.

## Token colours on dark panes stop following the OS

The syntax palette ships light and dark variants switched by the OS setting,
but the diff rows and the peek preview have hard-coded dark chrome. On a
light-mode machine that meant near-black tokens on a near-black background. The
dark palette is now pinned for those surfaces, while the preview pane's code
blocks keep following the system as they should.
