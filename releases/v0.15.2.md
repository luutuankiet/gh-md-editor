# v0.15.2 — `upgrade`: move every running server onto a new version with one command

- **`npx -y @luutuankiet/gh-md-editor@latest upgrade` restarts every running server onto the version it just fetched.** The npx fetch *is* the upgrade; the subcommand walks the registry and moves live servers onto that tree. No more finding the original command on each box, killing it by pid, and retyping the flags from memory.
- **Each server is replayed from its own registry entry** — same port, same bind host, same workspace, same auth token, so existing `?token=` bookmarks keep working. `--tunnel` servers are the exception and say so: a public URL is minted fresh on every start, so the old one is dead.
- **It never prompts.** Unlike `down`, live terminal sessions here are collateral of a restart you explicitly asked for rather than something being thrown away, so they are reported afterwards instead of confirmed beforehand.
- **Run it from a terminal panel inside a server it is about to kill and it hands off.** That shell would die mid-restart and the new server would never start, so the work re-execs into its own session and finishes after the old shell is gone. The marker is an environment variable the server already sets on every pty it opens, which means no process-table scraping and identical behaviour on macOS.
- **Servers already on the running version are skipped** — what makes a stale global install announce itself instead of silently restarting everything. `--force` restarts them anyway; `--dry-run` prints the plan and stops.
- **`list-servers` gained a VERSION column.** Registry entries now record the version and tunnel binary a server was started with; entries written by older servers show `?` and upgrade normally.
