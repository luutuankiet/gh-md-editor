# v0.24.1 — the markdown source pane stops fighting the scroll

Patch for a regression shipped in v0.24.0: the markdown cockpit's source pane stuttered while scrolling and drifted back toward an earlier position, and right-clicking the preview jumped the source pane and then lost the jump.

- **A remembered scroll position no longer rebuilds the editor that owns it** — the effect that constructs the CodeMirror view read the tab's saved anchor reactively, while the scroll listener it installs writes that same record. One scroll assignment measured ten full view rebuilds; the `{line, off}` anchor round-trip is slightly lossy, so the position also crept 347px backwards on its own. The read is now untracked.
- **Same class of fix on the preview pane** — its saved pixel offset was read reactively too, so every scroll tore the effect down, re-armed the growth-retry observer, and re-asserted a stale offset while the reader was still moving.
- **Right-click reveal from the preview holds again** — it always fired, but the rebuild loop dragged it back, and each teardown cancelled the pending 150ms save, so the tab kept restoring a position from before the jump. The revealed line is now what gets persisted, and the caret survives.
- **Nothing changes outside the markdown cockpit** — the code and diff tabs already untracked their restore reads and never regressed; the standalone and browser-extension builds pass an empty tab key, so the affected block never executes there.

Per-tab wrap, scroll, diff layout and language behave exactly as v0.24.0 documented. No storage format change, so tabs remembered under v0.24.0 restore unchanged.
