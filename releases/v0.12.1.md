# v0.12.1 — the git panel follows the workspace you opened

- **The repository picker is anchored to the open workspace, not the directory the server was started in** — serving a container of checkouts (`~/dev`) and opening one project inside it used to offer every sibling repo, and mounted whichever one happened to sort first. Opening a *subdirectory* was worse: the workspace was matched against the repo list by exact string equality, so a folder nested inside a checkout never matched and fell through to that same wrong default. `/api/git/repos` now takes the workspace as `?base=`, resolved through the same escape guard as status, diff and action, and still returns repo ids relative to the start directory — no other endpoint's contract moves. The scan climbs from the anchor to find the enclosing checkout before it descends, so anchoring anywhere inside a project resolves to that project; the climb stops at the start directory, since a repo above it is unaddressable by every other endpoint and must not be offered.
- **Refresh re-anchors instead of only refetching status** — opening a workspace in another window and pressing ⟳ re-scopes the picker to what is actually in range, and a selection that has gone out of range is dropped rather than left in the header pointing at a repo you can no longer see. Previously the button rescanned repositories only when the list was empty, so it could never correct a wrong anchor.
- **An anchor holding no repository now shows an empty picker** rather than falling back to a scan of the start directory — that fallback is what mounted the panel on an unrelated project in the first place.
