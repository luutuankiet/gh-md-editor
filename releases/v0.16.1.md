# v0.16.1 — Diffs you can edit, with the whole file around them

Every diff in server mode was a read-only list of changed hunks: to fix something you noticed while reading one, you had to open the file in another tab and find the line again. The incoming side is now a real editor, the unchanged parts of the file are present and folded out of the way, and the whole thing is syntax highlighted. Everything below is server mode (`npx @luutuankiet/gh-md-editor`).

- **The incoming side of a diff is editable** — type in the right pane and it saves itself shortly after you stop, or `Cmd+S` to save at once; an indicator shows work that has not landed yet. If something else wrote the file after the diff loaded, the save stops and says so instead of quietly overwriting. Diffs with nothing on disk behind them — a staged snapshot, or two commits pinned against each other — stay read-only, because there is no file for an edit to land in.
- **The rest of the file is there, collapsed** — the unchanged stretches between hunks are folded into a labelled strip carrying the number of lines it hides. Click one to read the surrounding context in place, without opening the file elsewhere. Both editor views do this.
- **Three ways to read the same diff** — side by side, inline, or the familiar list of hunks; the choice is remembered by the browser. The hunk list keeps line-level staging and reverting, which needs a patch and therefore has no editor equivalent. The editor views offer the operations that do make sense there: restore a whole region to the version on the left, or mark one reviewed so it stops standing out.
- **Stage and commit from inside the diff** — a message box and two buttons above the file, so a one-line fix no longer requires a trip to the source-control panel and back.
- **Diffs are syntax highlighted** — they had been rendering as plain text. Single-file component formats carry no grammar of their own in the editor's language catalogue, so `.svelte`, `.astro` and `.vue` now fall back to HTML, which already understands the script and style blocks that make up most of such a file. Code tabs use the same fallback, where those files previously opened unhighlighted as well.
- **Long file names are reachable in every tree** — the explorer, the outline, source control and branch comparison scroll sideways instead of cutting names off at the panel edge, and section headings stay pinned to the left while they do. A related fix: names beginning with a dot are no longer drawn with the dot at the wrong end.
