# v0.18.0 — a status bar, a commit graph, and diffs against files that do not exist yet

The last release gave the explorer hands. This one is about the two things you look at between edits: the state of the repository, and the difference between two versions of something. Both used to mean leaving the page. Everything below is server mode (`npx @luutuankiet/gh-md-editor`).

## A status bar

- **The bottom strip now says where you are.** Host on the left, then the branch, how far ahead or behind it is, and how many files have changed. It is the answer to the question you were opening a terminal to ask.
- **Click the branch to switch it.** Branches, tags and recent commits in one picker, with the checkout run for you and the tree refreshed after.
- **A workspace with several repositories picks one to report on.** The anchor is yours to choose and it is remembered; without it the strip would have to either lie or stay blank.
- **The open file's size in tokens sits at the right end.** Not bytes — tokens, because the number that decides whether a file fits in a model's context is the one worth showing. `Copy for context` in the explorer now reports the same figure for the whole selection when it finishes, so a twelve-file copy tells you what it just cost before you paste it somewhere.

## A commit graph

- **`Git Graph` opens the history as a graph**, lanes and merges drawn the way a graph client draws them, in a tab rather than a panel so it gets the whole width.
- **Click a commit to see what it touched.** Its files list; clicking one opens the diff against its parent.
- **Open the file, not the diff.** A commit tells you where to look, and once you know, what you usually want is the file as it stands now. That is one click from the same list.

## Diffs

- **Compare a buffer you have never saved.** A new untitled tab can be compared against a file or against the clipboard. Neither side needs to exist on disk — you can diff a scratch buffer against pasted text, which is the shape most "why are these different" questions actually arrive in.
- **The right-hand side is editable, and the arrows in the middle work.** Copy a change from the reference side onto yours without leaving the diff. When the side you are editing is a real file, edits save themselves as always; when it is a scratch buffer, they flow back into the tab that owns it, so switching away does not lose them. The header says which of the two you have — `scratch` where there is no file behind the text.
- **Split view scrolls in both directions, wraps on request, and keeps the two columns in step.** Horizontal scrolling used to move one column and leave the other behind, which is the one thing a side-by-side view must not do.

## Reading code

- **Sticky scroll.** The declarations you are inside stay pinned at the top of the editor as you scroll past them. They are drawn translucent on purpose: the code behind them is still readable, so the pin costs you context instead of buying it.
- **The breadcrumb names the symbol you are in**, not just the file, and follows the cursor. It works on an unsaved buffer too, once you pick a language for it from the selector.
- **Ctrl/Cmd-click a symbol to jump to where it is defined.** Same-file definitions resolve from the outline; anything else falls through to a project-wide search for the declaration.
- **Indentation is tinted by depth.** Four colours cycling, with a distinct one for lines that mix tabs and spaces — which is usually a bug you would rather see than not.
- **Values in a `.env` file are hidden until you ask.** Toggle from the command palette, or reveal one line at a time. It is a cloak over the display and nothing more: the file on disk is untouched, so this is protection from a shoulder or a screen share, not from anything else.

## Explorer and terminal

- **Drag files in from the desktop to upload them.** Folders come in whole, progress is shown per file, and anything that would overwrite something is listed and asked about once, before a single byte moves.
- **The terminal wraps long lines on request and turns urls into links.** Scrollback survives a panel toggle, and the shell starts with a sane locale so box-drawing characters and emoji land where they should.
- **Ignored files are dimmed in the tree** rather than hidden, which keeps `.gitignore` honest without hiding the build output you occasionally need.

## Fixes

- **A save that fails now says so.** Any response other than success or a conflict was being dropped on the floor: the tab kept its unsaved dot, the file on disk kept the old contents, and nothing on screen said the write had been refused. Dropped connections did the same, silently. Both now raise the error they got.
- **Files that cannot be replaced are written through instead.** Saving is a write-to-temp-then-rename, which is what makes a save atomic — but a rename cannot replace a bind-mounted file, or a target on another filesystem, and those saves were failing with a resource-busy error. They now fall back to writing the bytes in place, which keeps the file where it is. Failed saves also clean up their temporary file rather than leaving it beside the original.
- **Assets are pre-compressed at build time and served with immutable caching.** The bundle arrives about a third of the size over a slow link, and a reload after that mostly does not arrive at all.
