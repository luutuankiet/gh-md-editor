# v0.26.0 — one repository, chosen once

Server mode now agrees with itself about which git repository you are looking at, and says something useful when the answer is "none".

## One anchor for every git surface

The status bar, Source Control, Tree Compare and Git Graph each used to scan for repositories on their own and pick their own default. In a workspace holding more than one checkout they could disagree, and the disagreement was invisible: the bar named one repository while the commit button acted on another.

There is now a single anchor, chosen in the status bar and shared by all four. The repository dropdowns in Source Control and Tree Compare are gone — those panels show which repository they act on and nothing else.

- The choice is remembered per workspace, so reopening a folder restores it.
- **Open Git Repository…** in the command palette opens the picker from the keyboard.
- Committing with nothing anchored is refused. It used to resolve to the served root — a repository you had not chosen and could not see.

## The picker groups worktrees under the repository that owns them

Open a workspace on a linked worktree and the picker shows the owning checkout and its sibling worktrees beside it, folded by default unless the one you are in is inside. Folds are remembered per workspace, like the anchor.

## Broken worktree links are explained, not repaired

A git worktree is held together by two absolute paths written into two small text files — one inside the worktree, one inside the repository that owns it. Move either side, with `mv` or by restoring a backup somewhere new, and git stops recognising the checkout and reports only `not a git repository`.

Server mode now recognises that state specifically. It tells you what happened, which repository the worktree belongs to, and the exact command that puts the link back:

```
git -C "/path/to/owning/repo" worktree repair "/path/to/worktree"
```

The command is copyable straight from the picker. **It is not run for you.** Working out the owner is an inference, and repairing on a wrong inference silently de-registers a worktree that was working perfectly well. The editor blocks instead: a checkout git cannot open is never handed to the git panels as though it could be.

When no owner can be proven — both halves of the link moved and the repository was renamed too — the message says so rather than guessing at a path.

Submodules whose git directory is missing are now reported as submodules, pointing at `git submodule update --init` rather than a worktree command.

## Also

- Git Graph says `no repository` instead of printing a repository name and `0 commits` for something it never queried.
- Tree Compare no longer claims `No differences.` about a comparison that has not run.
- A repository sitting inside the workspace no longer stays hidden behind a broken checkout above it in the tree.
- The repository scan reports paths as git spells them, so a workspace reached through a symlink no longer lists the same checkout twice.
