# v0.25.4 — a diff can open the file whole, at either of its own two ends

- **A diff header now names the refs it is comparing, and each name is a button.** A diff answers "what changed"; it is bad at "what does this file actually look like at that commit", which is the question that follows about half the time. The header already read `origin/main vs v0.7.4`; those two refs are now clickable and open the file whole, read-only, at that ref. A third button opens it at `HEAD` whenever neither end is already there — so a compare against an old tag is one click from the current state without touching the compare.
- **Named, not glyph-only.** The commit graph and the tree compare panel spell this action as a bare clock glyph on row hover, which is invisible until you find it by accident. A diff has room for the label, and three identical clocks in a row would say nothing about which commit each one opens, so each button reads `◷ v0.7.4`, `◷ origin/main`, `◷ HEAD`. Blue is the incoming side, matching the rest of the git panels. A working-tree diff shows just `◷ HEAD`; an untracked file, which exists at no ref, shows none.
- **Also in the command palette.** `Open Diff's File at This Commit` and `Open Diff's File at HEAD` act on whichever diff is on screen. "This commit" is the diff's old side — the state the change departed from.
- **Opening a file at a ref no longer closes the diff that asked for it.** The preview slot recycles the first unpinned, unmodified tab, and when the click came from a diff header that tab was the diff itself: the comparison vanished to show one of its own sides. A diff is a reference view meant to be read beside the file it opens, so it is now exempt from the preview slot while it is the tab on screen. Every other unpinned clean tab is still fair game.
- **Ship fix carried from v0.25.3.** A web release bumps `server/package.json` as well as the root manifest. The publish workflow builds the tarball from `server/`, so a root-only bump produced a tag that built cleanly and was then rejected by the registry for republishing the previous version.

No storage format change and no server change.
