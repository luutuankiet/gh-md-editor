# v0.25.5 — find opens every fold it hits, and a commit means the commit you are reading

- **Find in a diff now opens every collapsed strip holding a match, not just the one you step onto.** v0.25.3 unfolded a hidden match on arrival, which is right for walking hits one at a time with the arrow keys and useless for the thing find is actually for: looking at all of them at once. The rail already knew where every match was and drew the buried ones hollow; those strips now open as soon as the query is live, both columns together, one dispatch per column. The query has to be two characters before anything unfolds — a single letter matches most of a file, and folds do not come back without rebuilding the view. Typing is debounced, so a query is walked once when it settles rather than once per keystroke.
- **`Open Diff's File at This Commit` now opens the commit you are looking at.** It opened the diff's OLD side, and a commit's diff is drawn against its parent — so for any file the commit added, it asked git for a blob that has never existed and reported the file as missing. That reading of "this commit" was wrong: the commit being read is the one meant. The old side keeps its own entry, `Open Diff's File at Base Commit`, and the first commit of a repository no longer offers a parent that is the empty tree.
- **When a file genuinely is absent at a ref, the message says so.** `Not in 3f3e067: no such object` is git's phrasing for a lookup that found nothing, and it reads like a fault. It now reads `Not in 3f3e067 — the file did not exist at that commit.`
- **A file opened at a ref gets its syntax highlighting back.** The tab is titled `app.js @ v1.2` so two commits of one file can sit side by side, and that title was also what grammar detection was handed — which reads the extension off the end of the string and so resolved `js @ v1.2`, matching no language. Every ref-opened file has been plain text since the feature landed, whatever its type. The bare name now travels with the tab, separately from the label on it.
- **The diff header offers the working copy, and stops inventing a `HEAD` that is not in the diff.** A comparison between two commits used to grow a third button for `HEAD`, an unrelated version of the file wearing the same clock icon as the two being read. The header now shows only refs the diff is built from, plus `↧ file`, which opens the actual file on disk — editable, with its history and its gutters, the same thing the explorer opens. `Open Diff's File` is the palette twin. `HEAD` still appears where it is genuinely the diff's own side, which is every diff of the working tree.

No storage format change and no server change.
