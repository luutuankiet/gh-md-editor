# v0.20.0 — one word wrap setting

Word wrap used to be four separate settings that did not know about each other.
Turning it on in the diff left the code editor unwrapped; the markdown editor
kept its own, defaulted the other way; the merge view added a fourth. Checking
whether a given surface had wrap wired up at all was its own chore.

There is now one preference, stored once and shared by every text surface:

- the markdown editor and its preview
- the code editor (Alt/Opt+Z)
- both diff panes, in split and inline, and the patch columns in hunks view
- all four merge panes
- search results

Toggle it anywhere — the Wrap button in the diff or merge toolbar, Alt/Opt+Z in
either editor — and every other surface follows immediately. It survives a
reload, and a second tab open on the same workspace picks up the change as it
happens rather than at its next refresh.

## Search results wrap now

They were the one surface with no wrap at all: a hit in a minified bundle or a
deeply indented block ran off the edge of the panel. With wrap on, a long hit
uses as many rows as it needs. With wrap off you keep the horizontal scroller,
which is still the better way to read a hit in aligned or columnar text.

## Upgrading

Nothing to do. Whichever of the old settings you had touched is adopted as the
new shared one the first time you load this version, and the superseded keys
are cleaned up. If you had never changed any of them, wrap starts on.
