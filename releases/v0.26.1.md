# v0.26.1 — the Git Graph tab stops forgetting

Open a commit in Git Graph, click one of its files to read the diff, then click back to the graph. Until now the graph came back blank: no commit selected, the detail pane shut, the file tree unfolded, the commit list scrolled back to the top. Every read of a commit that touched more than one file meant finding your place again.

The editor renders only the active tab of a group, and it builds it fresh each time you switch to it. Everything a tab held in memory goes when you leave it. The other tabs have long kept the parts worth keeping — scroll offset, word wrap, which of split/inline/hunks a diff was in — in a small per-workspace store that outlives the tab and outlives the page. Git Graph was the one tab never wired to it.

It is now. A Git Graph tab remembers:

- which commit has its detail pane open,
- which folders you had folded in that commit's file list,
- where both the commit list and the detail pane were scrolled.

All of it per workspace, and all of it across a full browser reload, not just a tab switch.

The commit itself is re-fetched rather than cached. What is written down is the forty-character sha; the message body and file list are asked for again, so an amend or a rebase between visits shows the commit as it is now instead of a stale copy. A sha that no longer resolves — rebased away while you were elsewhere — closes the pane quietly instead of raising an error for a request you did not make this time.

## Git Graph tabs survive a reload at all

They did not. Reopening the browser rebuilds the previous session's tabs from a saved list of what each one was, and a Git Graph tab never recorded which repository it was drawing. The restore code was already looking for that field and had never been given it, so every graph tab fell through to being treated as a file on disk, was not found there, and was dropped without comment.

## Merge tabs survive a reload too

The same omission, the same silent drop. Conflict resolution tabs now come back with the rest of the session. They carry no state of their own to restore — the merge view re-reads git's staged versions of the file every time it mounts — so a tab reopened after the conflict was resolved elsewhere says exactly that and shows the working copy, rather than reconstructing a merge that is already over.
