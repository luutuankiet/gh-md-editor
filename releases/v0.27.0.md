# v0.27.0 — images and PDFs open as previews

Server mode used to open a picture or a PDF as a tab reading `is a binary file.` They now open as what they are.

## Images

PNG, JPEG, GIF, WebP, AVIF, BMP, ICO and SVG open in a preview, fitted to the pane on a checkerboard so transparency is visible. The bar under it shows the pixel dimensions and the file size.

- **Click to zoom to 100%**, centred on the point you clicked. Drag to pan, click again to fit. An image already smaller than the pane is shown at actual size and the click does nothing.
- **SVG is both a picture and source.** It opens as a preview with an **Open as text** button that turns the same tab into the editor. Scripts inside an SVG do not run: it is only ever loaded as an image.

## PDFs

A PDF opens in the browser's own PDF viewer, embedded in the tab, with its paging, zoom, search and outline. Nothing is bundled for it. A PDF over the 5 MB text-read cap previews like any other, because the preview decision is made from the file name before anything is read.

## Previews follow the file

A preview notices when its file changes on disk and reloads within two seconds, with no click and no focus change. Re-running a render script in the integrated terminal updates the slide or PDF you are looking at. Zoom is kept across a reload, unless the new image fits the pane.

A PDF reloads from its first page.

## Under the hood

- A new endpoint, `GET /api/raw?path=`, serves a file's bytes with its real content type, `content-disposition: inline` and `nosniff`. It answers only for the extensions above; anything else is a `415`, so it cannot be used to serve HTML under the editor's origin. `HEAD` returns the same headers with the file's mtime and no body; that is what the preview polls.
- Picture tabs saved by an older version as binary placeholders come back as previews after the upgrade.
