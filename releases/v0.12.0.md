# v0.12.0 — background servers: `up`, `list-servers`, `down`

- **`gh-md-editor up` starts a detached server and returns** — the point of server mode was always to ssh into a box and open the editor from a phone, but the server died with the ssh session that started it. `up` now spawns it as a session leader, so the `SIGHUP` at logout never reaches it, and prints the url, pid and log path before exiting. It does not guess a sleep: it waits for the server's own registry write, which only happens once `listen()` has succeeded, so a port already in use or an unreadable workspace is reported to the terminal that asked — with the tail of the log — instead of vanishing into the background.
- **`list-servers` shows every running server and a url you can actually open** — pid, port, uptime, live terminal count, workspace and link, across every workspace on the box (alias: `ls`). State is one JSON file per port under `~/.cache/gh-md-editor/servers/`, written by the server, never by the caller — that is the only moment the port is confirmed bound and the auth token is final, since a bare `--tunnel` mints its token server-side. Liveness is never read from the file: a `kill(pid, 0)` probe is the source of truth and stale entries are reaped on every read, so a `kill -9` self-heals. Those files carry the token, so the directory is `0700` and the files `0600`.
- **`down` stops servers, and asks first when shells would die with them** — exactly one running stops it outright; several give an arrow-key picker showing each server's live terminal count; `--port <n>` and `--all` cover the scripted cases. It signals `SIGTERM`, never `SIGKILL`, so the server's existing shutdown path sweeps the pty children it spawned rather than leaking them, and escalates only if the process is still there eight seconds later. Live terminal sessions are the one thing restarting cannot bring back, so they prompt — `--yes` skips it, and a run with no tty refuses rather than guessing.
- **`-p` is now an alias for `--port`** everywhere, in the foreground server as well as the new subcommands.
- **No new dependencies** — the picker is built on `node:readline` in raw mode. The published package still ships `ws` plus the optional `node-pty`, and install weight is unchanged.
- Running with no subcommand still starts a server in the foreground exactly as before.
