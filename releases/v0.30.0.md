# v0.30.0: LookML highlighting, and search results that never wrap

In server mode, LookML files opened as plain text, and search results wrapped long hits over several lines whenever word wrap was on, which made a busy result list hard to scan. This release adds LookML syntax support to code tabs and keeps every search hit on one line.

## LookML in code tabs

- **`.lkml` files open as LookML.** That covers view, model and explore files such as `orders.view.lkml`. The language picker lists `LookML`, so you can also pick it for an untitled buffer.
- **Keys, strings, comments, numbers and `yes` / `no` each get their own color,** and so do `asc` / `desc`, field references such as `orders.id` or `-user_id`, and `{ }` and `[ ]`.
- **SQL inside `sql:` and `expression:` blocks is colored as SQL,** up to the closing `;;`, even across many lines. `sql_trigger_value:`, `sql_on:` and the other `sql_*` keys work the same way. After the `;;` the line goes back to LookML colors.
- **`${...}` substitutions stand out everywhere,** including in the middle of SQL, so `${TABLE}.id` and `${orders.SQL_TABLE_NAME}` are easy to spot.
- **`html:` and `js:` blocks are shown as one string,** up to their `;;`.
- **Editor basics work as in other languages.** `Ctrl/Cmd+/` toggles a `#` comment, `{ }` and `[ ]` blocks fold from the gutter, brackets match, and typing `{`, `[` or `"` adds the closing character.
- **Old `.lookml` dashboard files open as YAML,** which is what they are.

## Search results never wrap

- **Every search hit stays on one line,** like the Explorer file tree. When a hit is wider than the panel, scroll the results sideways.
- **The word wrap setting no longer changes search.** It still applies to the code editor, markdown, diff and merge views, and it is still on by default.
