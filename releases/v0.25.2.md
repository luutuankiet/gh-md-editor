# v0.25.2 — Alt/Opt+click drops a cursor in every editor, not just the markdown one

- **Alt/Opt+click now works in code tabs and in both columns of a diff.** The shortcut sheet, the web app's help text and the extension's welcome page had all advertised it as an Editor shortcut, but only the markdown editor ever implemented it — the code editor and the diff panes had no mouse gesture for multi-cursor at all. Every surface now shares one extension, so the chord cannot drift per pane again.
- **Alt/Opt+click on an existing cursor takes it away.** Overshoot no longer means starting the selection over; click the stray caret and it goes.
- **Cmd+D in a diff spawns cursors instead of collapsing to one.** The diff panes never enabled multiple selections, so the walk-to-next-occurrence command quietly kept a single range no matter how many times it ran. The same extension that carries the mouse chord carries the flag.
- **Ctrl/Cmd+click keeps whatever it already meant.** In the markdown editor it still adds a cursor, which is CodeMirror's own default on each platform — the facet that selects the modifier reads only its highest-precedence provider, so naming Alt without naming the platform default would have taken the platform default away. In code tabs it is still Go to Definition, which claims the event before the selection machinery sees it.
- **The hand-rolled mousedown handler is gone.** It had been added on the theory that CodeMirror shipped an Alt+click multi-cursor that Firefox on macOS was intercepting. There was no such built-in — the library's default modifier is Cmd on macOS and Ctrl elsewhere, and there is no browser-specific branch anywhere in its mouse code. Going through the documented facet instead is what makes the removal half work, since the library's own mouse selection is the part that knows a click landed on an existing cursor.

No storage format change and no server change; the behaviour is entirely browser-side and applies to the web app, the server IDE and the VS Code extension's editor alike.
