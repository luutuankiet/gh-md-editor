# v0.28.0 — editor tabs wrap onto rows, and tabs get a right-click menu

In server mode, the editor tab strip was a single row. With more tabs open than fit, it scrolled sideways behind a horizontal scrollbar, and every tab printed its folder path, so few tabs fit at all. The strip now behaves like VS Code with wrapped tabs.

## Tabs wrap

- **Tabs that do not fit wrap onto a new row.** There is no horizontal scrollbar.
- **The strip grows to at most 3 rows,** then scrolls vertically inside itself. The active tab is always scrolled into view, whether you opened it from the explorer, quick open, go to definition or a restored session.
- **Every tab shows its full name.** A tab is as wide as its name, with no ellipsis. The only exception is a name wider than the whole editor group.
- **Split groups wrap independently,** so a narrow group wraps more than a wide one.
- **Drag and drop knows about rows.** Dropping a tab on row 2 or 3 lands it where the caret shows. Before this, the slot was picked from the horizontal position alone, which put it on the wrong row once tabs wrapped. Dragging into another split group works as before.

## Folder labels only when needed

A tab shows its folder only when another tab in the same group has the same file name, and only as much of the folder path as tells them apart (`docs` next to `releases` for two `README.md` tabs). Close one of them and the other tab's label goes away. The full path is still in each tab's tooltip.

## Close button and unsaved marker

As in VS Code, `×` shows only on the active tab and on the tab under the pointer. An unsaved tab shows `●` in its place, which turns into `×` on hover. The slot is always reserved, so tabs never change width on hover and rows never reflow under the pointer.

## Tab right-click menu

Right-click any tab for **Close**, **Close Others** and **Close All**. It looks and dismisses like the recent-workspaces menu: click outside or press Escape. Escape now also dismisses the recent-workspaces menu.

**Close Others** keeps the tab you right-clicked, even if it was not active, and makes it the active tab. It still keeps exactly one tab across the whole window and closes the rest in every split group.

## One confirm for a bulk close

Close Others and Close All, from the tab menu or the command palette, now ask once and list every unsaved file. Cancel closes nothing. Before this, you got one dialog per unsaved file and Cancel only spared that one file. Closing a single tab still asks about that one file, as before.
