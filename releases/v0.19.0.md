# v0.19.0 — the merge editor grows up

The three-way merge view shipped in an earlier release as a reader: it could
show you what each side said and splice one of them into the result, but the
sides themselves were plain text in a `<pre>`. No colour, no wrap, no way to
act on a conflict without going back up to the toolbar. This release rebuilds
those panes as real editors and closes the loop back to Source Control.

## Syntax highlighting in every pane

Current, Base and Incoming are now CodeMirror views in their own right,
resolving the same grammar the Result pane already used. A Python conflict
reads as Python on all four panes instead of one.

## Word wrap, once, for the whole view

The merge toolbar gained a `Wrap` button that drives all four panes together —
including the Result editor, which until now only answered to its own
Alt/Opt+Z. The setting is remembered between sessions. Long docstrings and
prose lines are readable in a 400px-wide pane again.

## Inline conflict actions

Each pane carries a codelens strip directly above the conflicting region:

- **Current** — Accept Current, Accept Combination (Current First), Ignore
- **Incoming** — Accept Incoming, Accept Combination (Incoming First), Ignore
- **Base** — Accept Base

`Ignore` takes neither change and restores the region to the common ancestor.
It needs the diff3 conflict style to know what that ancestor was, and says so
in its tooltip when the markers do not carry one.

Every accept is still an ordinary edit to the result buffer, so the editor's
own undo history covers it.

## Lockstep scrolling

Scrolling any pane scrolls the other three. The three sides are different
lengths, so this matches by fraction rather than by line — exact alignment is
not on offer, but four panes stay in the same neighbourhood.

## Resolve everything at once

`All current` and `All incoming` resolve every remaining conflict in the file
in one go, applied back to front so the offsets stay honest.

## Conflict blocks are visible in the Result

Every conflict still in the buffer is tinted, with the selected one brighter.
The result reads as a list of outstanding work rather than a wall of angle
brackets.

## Source Control finishes the merge

A merge in progress is invisible in git's porcelain output, so the panel never
knew one was happening. It now asks git directly and shows a **Merging** strip
with the number of conflicts left and a **Continue** button, enabled once they
are all resolved. The commit box is prefilled with the message git itself would
have offered — `Merge branch 'feature'` — with its trailing conflict advice
stripped.

The end-to-end path is: open a conflict, accept inline, **Complete Merge** to
stage it, then **Continue** in Source Control to commit.

## Also

The code editor accepts host-driven word wrap and decorative range marks, which
is how the merge view drives its Result pane. Neither changes behaviour for an
ordinary file tab.
