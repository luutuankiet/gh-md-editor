# v0.25.8 — carets in a column, menus that fit, and definitions that stay home

- **Shift+Alt+click spans a column of carets from the caret to the pointer.** Alt+click has dropped a single extra cursor for a while, but there was no way to place a run of them: holding shift as well fell through to the ordinary extend-the-selection gesture and produced one long highlight. It now does what shift+click does, one line at a time — a caret on every line between the one the caret is on and the one clicked, taking its column from the caret at one end and the pointer at the other. Lines too short to reach the column get a caret at their end rather than being skipped. The gesture completes on mouse-down with nothing to drag, and it works the same in the markdown editor, the code editor and both diff panes. Tabs count as the columns they render as, and a click past the end of a line still resolves to a column, so a ragged block selects the way it looks.

- **The explorer's right-click menu stays inside the window.** The menu was planted at the pointer and left there, so right-clicking a row near the bottom of a tall tree pushed most of it — including delete — off the screen with no way to reach it. It now opens below the pointer when there is room, flips above it when the whole menu fits there, and only when it fits on neither side does it cap its height and scroll. It is clamped horizontally for the same reason. Escape closes it, and clicks inside it no longer count as clicks outside: releasing the menu's own scrollbar used to dismiss it mid-drag.

- **New file and New folder create next to what is selected.** The two buttons above the tree always created at the top level of the workspace regardless of what was highlighted, which meant every new file in a nested folder started life in the wrong place and had to be dragged home. They now follow the same rule paste has always followed: a selected folder takes the new entry inside it, a selected file puts it beside itself, and the target folder is expanded first so the name box is visible. With nothing selected they still create at the workspace root — and clicking empty space in the tree now clears the selection, which is how you ask for that.

- **Go-to-definition no longer answers with other projects.** Ctrl/Cmd+click on an identifier sent no workspace scope at all, so the lookup searched the entire served root. On a root holding several checkouts side by side that meant definitions from projects that were not even open, reported as "4 candidates" and opened by absolute path. The lookup is now given the workspace the session is anchored to. The reference lookups behind the reference count and the references panel were scoped already, but by guessing the workspace from the first path segment of the open file — right only when the workspace sits exactly one level below the served root, too wide for a nested workspace and too narrow when the root is itself the workspace. All three now use the anchored workspace the rest of the app already knows about.

No storage format change, no API change. `/api/defs` gained no new parameter — it always accepted `path`, and the editor simply never sent it.
